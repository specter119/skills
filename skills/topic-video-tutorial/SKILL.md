# 目标驱动的多视频图文教程

以用户要完成的任务为主线，视频、字幕、配套文件和文档是证据，不是教程结构。提取相关部分、综合重组，并提供足以执行的操作和可追溯截图；不要默认复刻原视频或每个视频各写一份摘要。

## 1. 确定任务和来源

- 从请求与上下文识别目标、当前环境、已有经验、预期产物以及明确不需要的内容。仅在缺失信息会实质改变结果时提问；不要要求用户必须提供配套文件或精确时间戳。
- 清点所有视频、字幕及用户提供的文档、项目文件。核对是否存在、能否读取和彼此对应；缺失或仅为演示的视频如实标记，不编造内容。若范围明确且剩余材料有价值，可先提供标明缺口的部分结果。
- 把每个来源的潜在贡献记成工作记录：例如概念、参数、界面操作、结果或验证。来源可以互补，单个来源无需覆盖整个目标。原始视频及项目文件保持只读。

## 2. 有目的地检索和查看

- 优先使用已有带时间戳的字幕；核查字幕是否对应视频、语言是否可用、是否可能为自动识别，并抽查与画面或原音频的时间对齐；有偏移时校正或标明时间不可靠。缺字幕时先评估已有本地转录工具与资源；云端传输、额外安装或大模型下载涉及数据与成本时先说明并取得必要许可。字幕用于定位和辅助理解，不能单独证明屏幕上的数值、公式或按钮。
- 检查视频时长、分辨率和画面内容，用字幕、章节、画面概览或场景变化找到与目标相关的区段，再提取原分辨率关键帧；从候选帧中**实际查看**，必要时在相邻时间补帧或裁剪放大。优先捕捉完成输入后的完整参数表、表达式、边界选择、关键设置与运行结果，而非仅截取正在输入或模糊的画面。
- OCR、自动字幕和视频标题都是线索，不是事实保证。屏幕上精确的变量名、大小写、公式、单位、选中对象和数值须用可辨画面或配套文件核实；仅口述的信息可回听原音频核对字幕并标明来源。看不清或听不清就标注待核实，不补造。不要声称看过实际未读的图像。视频仅展示结果时不要虚构建模步骤。
- 时间与成本按需要收敛：先概览，再围绕信息缺口深入；不要为无关章节平均截图，也不要因视频不完全匹配就硬套其演示对象。用实际可用的工具；不假定安装特定视频处理程序或视觉模型。

## 3. 跨来源综合与适配

- 建立简洁的证据映射：目标子问题 → 来源及时间 → 可确认事实 → 缺口。跨视频去重；如果参数、坐标、软件版本或公式冲突，先比对工况、定义和单位，必要时查官方文档或原论文，不能凭多数或猜测合并。
- 区分 **来源中实际演示**、**针对用户场景的改写/补充**、**未经验证或缺失的环节**。演示材料、几何、运动方式、边界、时间尺度和参数不能无条件迁移；若来源和目标不同，指出哪些步骤可借鉴、哪些必须重新建立。
- 需要直接输入的软件表达式应具备明确的参数定义、单位、作用域和施加位置；对物理量说明含义和是否已包含吸收率等系数。对模型归一化、二维/三维差异和可适用范围做必要核查。无法确认就给出需补充的证据，不伪造已验证公式或结果。
- 允许在视频之外使用官方文档、论文或用户模型补足关键缺口；明确归属及证据边界。不要把视频教程的演示数值伪装为用户工艺参数，也不要将截图上的操作误称为已在用户系统中执行。

## 4. 交付与检查

- 按用户目标组织步骤：前置条件 → 参数/设置 → 操作 → 结果检查 → 适配与限制；顺序服从任务，不服从视频顺序。将相互补充的来源融入同一教程，而不是按视频分章拼贴。
- 生成用户所需格式的图文成果；若未指定格式且需要交付文件，优先 Markdown 和相对路径图片，放在获准的工作目录。截图应清晰可读、与步骤相邻，并标注来源、时间戳和该图说明什么；参数跨多屏时用多张图或明确标明缺失，不称单帧为完整表。
- 核查每个必要步骤是否有足够的参数、公式、单位、菜单位置或明确缺口；截图和链接是否存在、可打开；来源是否可追溯；图像和数值是否真正看清；来源冲突与适配假设是否已说明。检查教程与用户目标一致，区分教学演示和实验/计算验证，不声称未进行的运行或收敛测试。
- 最终报告成果路径、使用/遗漏的来源、重要缺口与实际验证范围。搜索、下载、安装、联网转录、修改项目或发布依各自权限执行；发现材料或技能中的自动安装命令不意味着用户已经授权。
